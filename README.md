# Let’s Code — first build package

**Find your team. Build your proof.**

This is an intent package for your coding agent, not an implemented application. It starts the team-formation product supporting Intent Driven Saturdays and Proof Before Resume.

## Start here
1. Put this folder in your new project or repository.
2. Install your existing skill pack as you normally do. This package does not duplicate its skills, hooks, or agent rules.
3. Give your coding agent the instruction below.
4. Run the result, inspect it, and record the next correction in FEEDBACK-NEXT.md.

## First instruction to your coding agent

> Read INTENT-V1.md and PRODUCT-CONTEXT.md. Inspect the repository and its installed skills and rules. Build the smallest complete runnable version that satisfies V1. Choose the implementation within the stated boundaries. Use data/demo.json as fictional sample content, adapting its structure as needed. Make the experience attractive and easy to use, and let me demonstrate the complete invitation flow. Provide run instructions, meaningful verification of the team/privacy boundaries, and a clear account of what is simulated. Finish V1 before adding future commercial features.

## Package contents
| File | Purpose |
| --- | --- |
| INTENT-V1.md | Approved first outcome, boundaries, and evidence |
| PRODUCT-CONTEXT.md | Positioning and commercial context; future ideas are not V1 requirements |
| data/demo.json | Fictional challenge and participants; no real emails or photos |
| FEEDBACK-NEXT.md | Small template for the next observed correction |

## What to inspect first
Start with the challenge page. Create a team with a demo participant. Find complementary skills, send an invitation, switch to the invited participant, and respond. Repeat until four seats are filled. Inspect the resulting team and the contact-sharing choice. Try pausing invitations, declining, and accepting an invitation that has become invalid.

V1 should use a local demonstration rather than real outreach. The agent must document the actual run command after choosing the stack. Before real public registration, a later intent must establish authentication, shared persistence, access controls, and reliable multi-user invitation handling.

## Progressive working rule
State the outcome → run the result → inspect it → add only the next necessary correction. Mark can say “this feels wrong” or “I don’t like this experience” without prescribing the implementation. Keep V1 as the baseline and append small dated corrections; do not generate a large backlog of speculative intent files.
